User guide

This guide explains how to set up and run calculations and how to read the results. The calculation method itself is described in Calculation method, the spring models in Spring models.

1. Running a calculation

A calculation is defined by an input folder containing Input.py, AdvancedSettings.py (optional, see below) and the pile and soil CSV files. The default input folder is Inputs/; every verification run has its own folder under Inputs/Verification/.

Start withWhat happens
run_abaqus.batRuns main.py in Abaqus/CAE without GUI, with the input folder INPUT_DIR set at the top of the .bat (default Inputs).
run_abaqus.bat <input folder>The same with another input folder (relative to the project folder or absolute). Dragging a folder onto the .bat file does the same.
run_abaqus_gui.bat [input folder]Opens Abaqus/CAE, runs main.py there and leaves the model open.

Example:

run_abaqus.bat Inputs\Verification\Thieken_Verification\offshore_30MN

The .bat files pass the input folder to main.py in the environment variable MONOPILE_INPUT_DIR (abaqus cae noGUI=main.py without it uses Inputs/). An input folder without its own AdvancedSettings.py uses Inputs/AdvancedSettings.py.

Paths: CSV paths in Input.py (PILE_CSV, SOIL_CSV, CPT_CSV) are relative to the folder of that Input.py; RESULTS_DIR is relative to the project folder. Absolute paths are allowed for both.

Both .bat files show the progress live in their window (the print output of Abaqus/CAE itself is not shown while it runs):

12:48:35  Start: 2 calculation(s) (pile x soil x spring model), input folder Inputs
12:48:35  [1/2] pile_thieken_ref/soil_thieken_ref/Thieken: started
12:48:35  [1/2] ...Thieken: model built (60 elements), 2 load levels, force control, H up to 3 MN
12:48:57  [1/2] ...Thieken: load level 1/2 done: H = 1.5 MN, mudline displacement 8.69 mm, rotation 0.064 deg, 6 iterations (0:00:22)
12:49:12  [1/2] ...Thieken: FINISHED (ok) after 0:00:37, results in results\...\Thieken
12:49:49  All calculations finished after 0:00:08: 2 ok, 0 with problems, see summary.csv

Lines with FINISHED are green, lines with FAILED, ABORTED or NOT converged red. The same log is saved as progress.log in RESULTS_DIR (e.g. results/progress.log).

Settings at the top of both .bat files:

SettingMeaning
set INPUT_DIR=Inputsinput folder used when no folder is given as argument
set STAY_OPEN=TRUEkeep the window open until a key is pressed; FALSE when the .bat is called from another script

Every combination of pile file × soil file × spring model is one calculation ("case"). The cases run one after the other; a failing case is reported and the next one starts.

2. Pile file (pile.csv)

One row per pile section, from the pile head downwards. Columns are found by their header names (any order, case-insensitive).

ColumnUnitMeaning
z_topmtop of the section, depth below the pile head
z_botmbottom of the section
diametermdiameter; top-bottom (e.g. 6-7.5) for a conical section
thicknessmwall thickness; top-bottom allowed
material–name from the material library (see below)
z_top, z_bot, diameter, thickness, material
0, 10, 6, 0.06, S355
10, 15, 6-7.5, 0.06-0.08, S355
15, 45, 7.5, 0.08, S355

Rules: the sections must be continuous (z_bot of one = z_top of the next), 0 < thickness < D/2.

Whether diameter is the outer or the mid-surface diameter is set with DIAMETER_REFERENCE in AdvancedSettings.py.

3. Soil file (soil.csv)

One row per layer, from the mudline downwards. Depths are below the mudline. The first line is a header; its names do not matter, because the columns are assigned by number in Input.py (section 6, see 4.7). Columns a model does not need are left empty and are listed as a warning.

ParameterUnitUsed byMeaning
z_top, z_botmalllayer boundaries below mudline (first layer starts at 0)
soil_type–allsand or clay
gamma_effkN/m³alleffective (buoyant) unit weight
phi°API, Kallehave, Sørensen, Thieken (required), PISA, Tott-Buswell (optional)friction angle
kMN/m³API, Kallehave (optional)initial modulus of subgrade reaction; default from the API chart
sukPaclay (all models)undrained shear strength; top-bottom allowed
eps50–claystrain at 50 % of the max. stress (default 0.01)
J–clayMatlock constant (default 0.5)
dr%PISA (sand layers, required), Tott-Buswell (optional, base shear, default 75)relative density (e.g. 75)
pisa_clay–PISA, PISA_CLAY (clay layers, optional)clay calibration: cowden (default, stiff till) or bothkennar (soft clay)
g0MPaPISA (sand, clay), Thieken, Tott-Buswell¹small-strain shear modulus G0 directly; top-bottom allowed
g0_ref, lambda_g0MPa, –PISA (sand, clay), Thieken, Tott-Buswell¹G0 = g0_ref·(σ_m/100 kPa)^λ
hb_b, e0–PISA (sand, clay), Thieken, Tott-Buswell¹G0 after Hardin & Black: B and void ratio
nu–ThiekenPoisson's ratio
es_ref, lambda_esMPa, –Thiekenoedometric modulus E_s = es_ref·(σ_m/100 kPa)^λ

G0 is taken per layer from the first complete group: g0, else g0_ref + lambda_g0, else hb_b + e0. The mean stress is σ_m = σ'_v (1 + 2k0)/3 with k0 = 1 − sin φ (k0 = 0.4 if φ is not given).

z_top, z_bot, soil_type, gamma_eff, phi, su, eps50, J, k, dr, g0, hb_B, e0, nu, es_ref, lambda_es, g0_ref, lambda_g0
0, 60, sand, 10.31, 40, , , , , , , , , 0.2, 70, 0.5, 106.3, 0.5

¹ TOTT_BUSWELL: only if the CPT file has no g0 column.

The soil profile must reach at least to the pile tip.

CPT file (TOTT_BUSWELL only). One row per CPT point, columns found by their header names (any order, further columns ignored):

ColumnUnitMeaning

4. Settings in Input.py

4.1 Files

SettingMeaning
PILE_CSVpile file, or a list of them; relative to the input folder
SOIL_CSVsoil file, or a list of them; relative to the input folder
CPT_CSVCPT file for TOTT_BUSWELL: one file for all soil files, or a dict {"soil.csv": "cpt.csv", …}; relative to the input folder. None if not used.
RESULTS_DIRoutput folder (default results); relative to the project folder, e.g. results/verification/PISA_Verification/C1_ultimate

Absolute paths are allowed.

4.2 Pile model

SettingMeaning
MODEL_NAMEname of the model in Abaqus/CAE
ELEMENT_COUNTnumber of beam elements over the whole pile (head to tip). Nodes are always placed at pile section boundaries, soil layer boundaries and the mudline; the elements are distributed over the intervals in between as evenly as possible.
ELEMENT_TYPEB31 (default), B32, PIPE31, PIPE32
MUDLINE_DEPTHdepth of the mudline below the pile head [m]; 0 = pile head at the mudline

4.3 Soil springs

SettingMeaning
SPRING_MODEL"API", "KALLEHAVE", "SORENSEN", "THIEKEN", "PISA_SAND", "PISA_CLAY", "PISA" (layered sand/clay), "TOTT_BUSWELL", or a list of them
LOADING"static" or "cyclic" (API-type curves only)
MAX_ITERATIONSmax. number of Abaqus runs per load level (spring iteration, displacement control)
TOTT_BUSWELL_ALPHATOTT_BUSWELL: residual base stress q_b,res = α·q_c at the tip (default 0.1)
TOTT_BUSWELL_COMPONENTSTOTT_BUSWELL: springs used, any of "p-y", "m-theta", "base" (default all)

4.4 Load

The load acts in the horizontal plane at the pile head: force H in the direction LOAD_ANGLE plus the moment M = H · LEVER_ARM.

SettingMeaning
LOAD_CONTROL"force": load levels k · ΔH up to HORIZONTAL_LOAD. "displacement": load levels with the mudline displacements k · Δv up to TARGET_DISPLACEMENT; H is found for every level.
HORIZONTAL_LOAD[N] force control: maximum load. Displacement control: estimate of H at TARGET_DISPLACEMENT, used only as a start value.
TARGET_DISPLACEMENT[m] displacement control: maximum mudline displacement (e.g. 0.1·D)
LOAD_ANGLE[°] direction from global X towards Y
LEVER_ARM[m] height of the load above the pile head
LOAD_INCREMENTstep width of the load levels as a fraction of HORIZONTAL_LOAD / TARGET_DISPLACEMENT (0.1 = 10 levels)
MAX_INCREMENTSmaximum number of load levels

4.5 Break criteria

All criteria refer to the mudline and are checked after every load level. None switches a criterion off.

SettingStops when
MAX_DISPLACEMENTmudline displacement ≥ limit [m] (e.g. 0.1·D, ULS in PISA)
MAX_ROTATIONmudline rotation ≥ limit [°] (e.g. 0.5)
VERTICAL_TANGENT_RATIO|rotation at the toe| / |rotation at the mudline| ≥ limit [–] (e.g. 0.01): the deflection line no longer has a vertical tangent at the pile toe

When a criterion is reached, the loading stops; the level that reached it is kept, and the load at the criterion is interpolated linearly between the last two levels. It is written to progress.log, summary.csv and marked in load_displacement.png. The case status is ok (break criterion).

4.6 Job and output

SettingMeaning
NUM_CPUSCPUs per Abaqus job
PLOTSTrue: create the PNG plots

The Abaqus job of every case is named <pile>_<soil>_<model> (characters other than letters, digits and _ replaced by _, at most 80 characters).

5. Settings in AdvancedSettings.py

Taken from the input folder; if it has no AdvancedSettings.py, Inputs/AdvancedSettings.py is used.

SettingDefaultMeaning
DIAMETER_REFERENCE"outer""outer": D in pile.csv is the outer diameter. "mid": mid-surface diameter: outer radius D/2 + t/2, which gives the thin-walled A = π·D·t and I = π·D³·t/8. PISA springs always use the mid-surface diameter (D − t with "outer").
SHEAR_FACTOR1.0transverse shear stiffness K = κ·G·A of the beam; None = Abaqus default; PISA used 0.5, IGtHPile 1.0
ITERATION_TOLERANCE1e-3convergence limit of the spring iteration and of the displacement control (relative)
RELAXATION0.5start value of the Aitken relaxation factor
CURVE_POINTS30points per spring curve (incl. 0)
GRID_START1e-4first curve point after 0 as a fraction of the curve range

For reproducing the PISA papers use DIAMETER_REFERENCE = "mid" with the D of the papers, SHEAR_FACTOR = 0.5 and material PISA_STEEL; for Thieken et al. (2015) "outer" and 1.0.

6. Output

6.1 Folder structure

Shown for RESULTS_DIR = "results":

results/
├── progress.log                    progress of the last run
├── summary.csv                     all cases (only with more than one case)
├── load_displacement_all.png       all load-displacement curves (more than one case)
└── <pile>/<soil>/<model>/          one folder per case, e.g.
    ├── <job>.odb                   Abaqus results of the last load level
    ├── <job>.cae                   model with the springs and load of that level
    ├── pile_head.csv               every load level
    ├── pile_profile.csv            last load level, every node
    ├── load_displacement.png
    └── pile_profile.png

6.2 pile_head.csv (every load level)

ColumnMeaning
increment, load_factorlevel number, fraction of HORIZONTAL_LOAD (force control) or TARGET_DISPLACEMENT (displacement control)
H [N], M_head [Nm]load and moment at the pile head
U1..U3 [m], UR1..UR3 [rad]pile head displacements and rotations (global)
v_mudline [m], psi_mudline [rad]displacement and rotation at the mudline in the main deflection direction
v_toe [m], psi_toe [rad]the same at the pile toe
iterations, convergedAbaqus runs of the level, convergence

6.3 pile_profile.csv (last load level, every node)

ColumnMeaning
node, z_pile [m], z_mudline [m]node and depth below pile head / mudline
U1..U3, UR1..UR3global displacements and rotations
v [m], psi [rad]displacement and rotation in the load plane
N [N], Q [N], M [Nm]axial force, shear force, bending moment in the load plane (Abaqus values)
Q_above [N], Q_below [N]shear force of the element above / below the node; the difference is the spring force at the node
SF_bend, SF_tip, SFThieken only: stretching factors at the node
qc [MPa], G0 [MPa], tau_f [kPa]TOTT_BUSWELL only: cone resistance, G0 and ultimate shaft friction at the node

How N, Q and M are evaluated from the Abaqus element values is described in calculation_method.md, section 8. After each case the console shows a plausibility check: M at the pile head must equal H·lever arm.

6.4 summary.csv (more than one case)

One row per case: input files (incl. the CPT file), status, load factor, H, displacement and rotation at the pile head and the mudline, max |M|, max |Q|, the break criterion and the interpolated load and displacement at it, and the folder.

Status values: ok, ok (break criterion), stopped at x % of the load (a load level failed), iteration not converged (level k) (spring iteration or displacement control did not converge within MAX_ITERATIONS at the listed levels), failed: ….

6.5 Plots

  • load_displacement.png: H over the mudline displacement and rotation, the break criterion marked.
  • pile_profile.png: deflection, shear force and moment over depth for the last load level.
  • load_displacement_all.png: all cases in one plot.

6.6 Overwriting

Running a case again deletes its .odb, .cae, CSV and PNG files at the start and writes them anew; other files in the folder and the folders of other cases are not touched. If the new run fails, the old results are lost. Use a separate RESULTS_DIR per input folder to keep results apart (as the verification folders do). summary.csv is only rewritten when more than one case is calculated.

7. Typical tasks

Compare spring models: list them in SPRING_MODEL; the soil file must contain the parameters of all of them.

Determine the load at a criterion (e.g. 0.5° rotation): set MAX_ROTATION = 0.5, a HORIZONTAL_LOAD well above the expected value and a fine LOAD_INCREMENT; read H_criterion from summary.csv or progress.log.

Load up to a displacement, e.g. 0.1·D (near the capacity): use LOAD_CONTROL = "displacement" and TARGET_DISPLACEMENT = 0.1 * D. This is more robust than force control close to the ultimate load.

Initial (small-strain) stiffness: force or displacement control with a small first level, e.g. TARGET_DISPLACEMENT = 0.0005 * D.

Several independent calculations: create one input folder per calculation (copy Inputs/ or a verification folder) and start each with run_abaqus.bat <input folder>; give each its own RESULTS_DIR.

Repeat a verification: e.g. run_abaqus.bat Inputs\Verification\Thieken_Verification\offshore_30MN, then python compare_thieken_ref.py (see Verification).

8. Troubleshooting

ProblemCause / remedy
Input folder '…' not found or without Input.pyThe folder given to the .bat (argument or INPUT_DIR) does not exist or has no Input.py.
Input file(s) not foundA CSV file named in Input.py is not in the input folder (paths are relative to the folder of Input.py).
Path of the Abaqus job files too longWindows limits paths to 260 characters. Use shorter CSV file names, a shorter RESULTS_DIR, or a shorter project folder.
job FAILED / stopped at x % of the loadThe Abaqus job did not converge, usually because H exceeds the capacity. Use displacement control or a smaller HORIZONTAL_LOAD.
NOT convergedThe spring iteration did not reach ITERATION_TOLERANCE within MAX_ITERATIONS; increase MAX_ITERATIONS, use smaller load steps.
phi missing, dr missing, soil parameters in soil.csvA required parameter is empty for a layer, or the column numbers in Input.py point to the wrong column.
WARNING: soil.csv column(s) not usedInformation only: columns the selected model ignores.
vertical tangent … reached already at the first load levelThe toe rotates with the pile from the start (short, stiff pile); the criterion cannot be met for this pile.
Window shows nothing for a long timeAn iterative model at a high load level can take several Abaqus runs of 15–30 s each; progress lines appear after every finished level.
Results of a failed case missingThe temporary job files (_work, .msg, .dat) are deleted at the end of a case. To inspect a failing job, comment out files.clean_up() in main.py temporarily.
