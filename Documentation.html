Automated Monopile Calculation (Abaqus)

Builds and solves 1D models of laterally loaded monopiles in Abaqus/CAE: the pile is a beam, the soil is a set of nonlinear springs (connector elements to ground) whose curves come from a selectable soil-spring model. Several piles, soil profiles and spring models can be calculated in one run and compared.

Main features

  • Pile from a CSV file: any number of sections, conical sections allowed.
  • Layered soil from a CSV file; nodes are placed at every layer boundary and at the mudline.
  • Force- or displacement-controlled loading in load levels, with a lever arm (H plus moment H·h).
  • Iterative spring models (PISA sand, Thieken) solved by fixed-point iteration with Aitken relaxation.
  • Break criteria: maximum mudline displacement, maximum mudline rotation, vertical tangent of the deflection line at the pile toe.
  • Results per case: .odb, .cae, CSV tables of the load-displacement curve and the pile profile (v, ψ, N, Q, M), PNG plots, and a summary of all cases.
  • Input folders: every calculation (e.g. each verification case) has its own folder with Input.py, AdvancedSettings.py and the CSV files, selected when starting the .bat.
  • Live progress in the console window.

The implementation has been verified against published results of PISA (Burd et al. 2020, sand, within 0.2 %; Byrne et al. 2020, clay, within 2–4 % with soil profiles read from figures; Burd et al. 2020b, layered soils, ultimate loads within 1.5 %) and Thieken et al. (2015); the Tott-Buswell model was checked for plausibility against Tott-Buswell et al. (2024), see Verification.

Requirements

  • Windows with Abaqus/CAE (tested with Abaqus Python 3.10; matplotlib from the Abaqus Python installation is used for the plots).
  • Windows PowerShell 5.1 (part of Windows) for the progress display.
  • No other Python packages are needed.

Quick start

  1. Put the pile and soil CSV files into the input folder Inputs/ (see Inputs/pile_thieken_ref.csv and Inputs/soil_thieken_ref.csv).
  2. Edit Inputs/Input.py: the files, the spring model(s), the load and, if needed, the break criteria.
  3. Double-click run_abaqus.bat (no GUI) or run_abaqus_gui.bat (opens Abaqus/CAE and leaves the model open). The window shows every finished load level and calculation.
  4. Results are in results/<pile>/<soil>/<model>/, e.g. results/pile_thieken_ref/soil_thieken_ref/Thieken/.

Other input folders, e.g. the verification cases, are run with run_abaqus.bat <input folder> (or by dragging the folder onto the .bat file):

run_abaqus.bat Inputs\Verification\PISA_Verification\C1_ultimate

Example Inputs/Input.py, comparing four spring models on one pile:

PILE_CSV = "pile_thieken_ref.csv"
SOIL_CSV = "soil_thieken_ref.csv"
SPRING_MODEL = ["THIEKEN", "API", "KALLEHAVE", "SORENSEN"]
LOAD_CONTROL = "force"
HORIZONTAL_LOAD = 30e6     # N
LEVER_ARM = 25.0           # m
LOAD_INCREMENT = 0.1       # 10 load levels

Project structure

AutomatedMonopileCalc/
├── Inputs/                default input folder
│   ├── Input.py           settings of a calculation (edit this)
│   ├── AdvancedSettings.py  rarely changed settings
│   ├── *.csv              pile and soil files
│   └── Verification/      one complete input folder per verification run
│       ├── Thieken_Verification/<run>/   Input.py, AdvancedSettings.py, CSV files
│       └── PISA_Verification/<run>/
├── results/               results (results/verification: verification runs
│                          with an explanation .md per group)
├── main.py                entry point run by Abaqus/CAE
├── run_abaqus.bat         start without GUI (live progress)
├── run_abaqus_gui.bat     start in Abaqus/CAE (live progress)
├── run_abaqus.ps1         helper of the .bat files (starts Abaqus, shows the log)
├── compare_thieken_ref.py comparison with Thieken et al. (2015), plain Python
├── methods/
│   ├── csv_reader.py      reading and validation of the CSV files
│   ├── geometry.py        beam model, mesh, cross-sections, materials
│   ├── connectors.py      soil springs as connector elements
│   ├── analysis.py        boundary conditions, step, load, job, odb reading
│   ├── solver.py          load levels, spring iteration, displacement
│   │                      control, break criteria
│   ├── postprocessing.py  pile_head.csv, pile_profile.csv, summary.csv
│   ├── plots.py           PNG plots
│   ├── progress.py        progress log
│   └── spring_models/     base.py (framework, shared curves) and one module
│                          per spring model
├── Documentation.html     start page of the documentation (this page)
└── docs/                  documentation pages (HTML) and style.css

Units

SI inside the model (N, m, Pa). Soil parameters in the CSV files use geotechnical units (kN/m³, kPa, MPa, degrees), see the user guide.
